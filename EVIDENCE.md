# Evidence

One row per criterion in `SPEC.md`, in the same sections and the same order. Every criterion outside **Assumptions**
has a row; a row with an empty cell is an unmet criterion. Assumptions are permissions rather than obligations, so there
is nothing to evidence — taking one is a choice, and belongs in `DECISIONS.md`.

The column asks what would **catch a violation**, not what passes. Naming a test that would still be green if the
behaviour broke is worse than leaving the cell blank, because it hides the gap instead of showing it. Where nothing
executable catches a criterion, name what does — a build failure, a type signature, a specific review of a named file.

Test names below are `Class#method`. The *sabotage meta-tests* (`SabotageMetaTest`) are the proof that a named test
catches: each disables one guarantee in the engine (a hook the public API cannot reach) and asserts the suite fails.

## Safety

Proof for the truncation check: `SabotageMetaTest#ignoringTruncationIsCaught`, with a measured sweep margin (previously provably zero), and `#deliveringPastARetentionDiscardedHoldInvertsCausalOrderAndTheOracleSeesIt` for the held shape. |

## Liveness

| # | What would catch a violation |
|---|------------------------------|
| 1 | The oracle observes the *feed*, not the engine's acceptance (D41): `SimProcess#feedOne` reports every fed message before the engine sees it, so at quiescence `Oracle#checkAllReceivedDelivered` fails on any message fed in a committed step and never delivered — unless it lay in the ground-truth delivered causal past of the execution that fed it (the D31 clamp's sanctioned drops) — and the scenario fails on any non-empty hold-back buffer, across crashes, restarts, truncation, topic death and declaration churn. A process that failed closed, or whose channel is wedged below the earliest retained position, has its liveness (not safety) checks waived — the liveness premises are unmet there. Proof: `SabotageMetaTest#silentlyDroppingAFedMessageIsCaught` (an engine consuming a position and discarding its message — the omission the acceptance-gated oracle provably could not see), plus a 33/120-seed sweep margin for that sabotage. |
| 2 | Sending happens unconditionally inside `ParsleyProcessor#send` (review: it consults the engine only to stamp the header, no deliverability path exists); behaviourally, every property run emits from processes that simultaneously hold blocked messages — a send that waited on deliverability would deadlock the drain fixpoint and fail quiescence. |
| 3 | `TargetedScenarioTest#causeOnPositionThatNeverYieldsResolvesFromReadPositionReport` asserts *no* delivery before the read-position report and delivery immediately upon it — the whole simulator is clock-free, so an implementation relying on elapsed time cannot pass it; `EndToEndIntegrationTest#causeOnAbortedPositionsResolvesFromReadPositionReports` proves the same-lifetime trailing-aborted-run case end-to-end, and `#causeOnTrailingAbortedRunResolvesEvenAfterARestart` pins the restart case the audit showed the host's committed offsets never cover — resolved by the facts source's read_committed probe (D35), whose absence makes that test hang. |
| 4 | `TargetedScenarioTest#causeOutsideReceivedChannelSetDoesNotBlock` and `#depOnDeadIncarnationOfRecreatedTopicDoesNotBlock` fail on any hold; property runs routinely hand receivers metadata naming channels they do not receive, where a block trips the quiescence check. |
| 5 | `TargetedScenarioTest#heldMessageIsDeliveredAfterRestart` (simulated full restart from committed state), `EndToEndIntegrationTest#heldMessageSurvivesARealRestart` (real stop and restart over surviving local RocksDB state) and `EndToEndIntegrationTest#heldMessageSurvivesAStateDirWipeByChangelogRestore` (local state wiped, ordering state rebuilt entirely from the changelog) fail if the held message is lost or undelivered. Content fidelity of the restored hold — key, value, headers, timestamp exactly as received — is asserted by `SimProcess#drain` on every delivery in every simulated run, and pinned by `TargetedScenarioTest#restoredHeldMessageReachesLogicWithContentIntact` at a non-zero position (persisting empty headers or a zeroed timestamp in `StoreCodec#encodeHeld` fails both — mutations that previously survived the whole suite). The reload path is pinned separately, since a hold's decoded form is dropped after persistence and read back when it reaches the head (D102): `ProcessEngineTest#aHoldReloadedFromTheStoreReachesLogicWithItsCausesIntact` fails if key, value, headers or causes differ after a flush and a restart, or if the reloaded causes stop entering the delivered past; `#aHeldMessageMissingFromTheStoreRefusesRatherThanDeliveringNothing` fails if a hold whose store entry is gone is delivered empty or skipped instead of stopping the process; and `#aHoldDeliveredBeforeItsFirstFlushIsNeverWrittenToTheStore` fails if a flush resurrects a delivered hold for a restart to deliver again. Proof: `SabotageMetaTest#losingHeldMessagesAcrossRestartIsCaught`. The corrupt-blob stop's diagnoses — which field's length was bad, against the bytes actually present — are pinned message-level by `StoreCodecCorruptionTest#headerValueLengthDiagnosisNamesTheLengthAndTheBytesRemaining` and `#sizedBytesLengthDiagnosisNamesTheFieldAndTheBytesRemaining`: deleting either length guard degrades the refusal to decodeHeld's undiagnosed catch-all "corrupt held blob" and fails them, while the classified refusal itself survives through that wrap (D94). |

## 2-safety

| # | What would catch a violation |
|---|------------------------------|
| 1 | Type-level: `Deliverability.decide`'s inputs are the causes, the received-channel set and the settled view — application state is not among its arguments, and `CorePurityTest` fails the build if the core package ever imports substrate, network or clock types it could smuggle state through. `ApiValidationTest#reservedStoreNamesAreUnconstructible` and `#storeNamesContainingTheReservedNamespaceAnywhereAreUnconstructible` fail if application state can alias ordering state — containment, not prefix: an embedded `__parsley.` composes a changelog inside the reserved namespace (`Store.of("q-__parsley.ordering")` under one process composes the ordering changelog of a sibling named `p-q`, which the prefix-only check accepted). The seam hands logic only declared stores: `TopologyWiringTest#stateReadFromAnUndeclaredStoreFailsClosedWithItsOwnReason` fails if an undeclared read is served instead of refused, and `#swallowedUndeclaredStoreReadStillFailsTheStep` fails if an application catch around its own handler can commit a step whose read was refused (the reader latches the refusal and the processor rethrows it after the handler returns). The latch holds across the whole delivery frame, not only the handler (D87): `#deserializerLatchedRefusalFailsTheStepEvenWhenSwallowed` fails if a refusal latched by the delivered payload's own deserializer — application code that runs before the handler — is erased by a frame reset, and `#serializerLatchedRefusalDuringPlanningFailsTheStep` fails if one latched during effect planning slips past the post-apply recheck. The throwing read-key shape is pinned alongside the returns-null one (D95): `TopologyWiringTest#throwingKeySerializerOnAStateReadFailsClosedEvenWhenSwallowed` fails if the reader stops wrapping-and-latching the key serializer's own exception, letting an application catch commit the step. |
| 2 | `TargetedScenarioTest#restartDoesNotChangeWhatIsDeliveredOrItsOrder` runs the same script three ways — no restart, restart between steps, and a crash that discards uncommitted receipts, deliveries and emissions — and fails on any difference in what is delivered or its order; every property seed interleaves restarts and must stay oracle-clean; `EndToEndIntegrationTest#heldMessageSurvivesARealRestart` shows the real pause-only restart; `BootstrapIntegrationTest#expiredOffsetsRestartFromEarliestNotTheDeclaredLatest` fails if a restart after offset expiry changes what is delivered (skipping via the declared LATEST, or redelivering past the session floor). |

## Fault model

| # | What would catch a violation |
|---|------------------------------|
| 1 | Every property run and most targeted scenarios interpose dead positions (aborted transactions, `appendDead`) between messages; an implementation assuming consecutive positions misjudges the settled frontier and trips the oracle or the quiescence check within a few seeds. |
| 2 | The simulator has no clock at all — timeouts, leases and speed assumptions have nothing to read, and arbitrary pauses are exactly its random interleavings (a process can sit unscheduled for hundreds of events, then resume on stale state and be aborted); an implementation needing time bounds cannot pass `CausalOrderPropertyTest`. The resume-on-stale-state commit case rides on host fencing — see Host obligation 6; the stale-bootstrap variant is closed by mechanism, not by an empty-group check: initial positions are committed through one generation-fenced group membership (D48), and `BootstrapIntegrationTest#staleBootstrapCommitIsFencedByGroupMembership` forces a newer lifetime between the stale bootstrap's read and its commit on a real broker and fails if the stale commit lands. Expiry restarts re-establish earliest, never the declared LATEST (D36), pinned end-to-end by `#expiredOffsetsRestartFromEarliestNotTheDeclaredLatest` under a real offset deletion. Two instances bootstrapping the same group together must both come up (D48's residual S1, closed by D108): `StreamsJoinCollisionTest#theBootstrapMemberWaitEndsWhenTheMemberLeavesAndGivesUpAtTheBound` fails if the pre-start wait stops polling until the other instance's member leaves, stops giving up at its bound, or treats a failed describe as evidence, and `#aRefusedJoinIsReplacedOnlyWhileTheBootstrapWindowIsOpen` fails if a refused join is replaced past that window or a persistent protocol conflict loses its substrate diagnosis; `ConcurrentColdStartIntegrationTest#twoInstancesColdStartingTogetherBothComeUpHealthy` corroborates on a real broker, where the collision window is probabilistic (three of eight rounds before the fix), so its green is corroboration rather than proof, and it counts a hung start or a client still rebalancing at the end of its settle window as a failure. The bootstrap's join wait is bounded and diagnosed (D48/D86, pinned by D95): `BootstrapMemberJoinTest#joinWithoutAnAssignmentFailsAtTheDeadlineNamingTheTimeout` fails if the deadline is dropped (the loop would hang; the double's poll budget surfaces it), `#protocolConflictAtTheDeadlineNamesTheLikelyHoldersAndCarriesTheCause` fails if the contested-group explanation or its cause is lost, `#interruptDuringTheProtocolConflictBackoffFailsTheJoinAsInterrupted` fails if an interrupt is swallowed into further backoff, and `#subMillisecondInheritedSessionTimeoutIsRefusedBeforeAnyNetworkContact` fails if an unusable inherited timeout reaches a consumer at all. |
| 3 | Property runs inject `crash()` at arbitrary points, including between receipt and delivery and between delivery and commit; `EndToEndIntegrationTest#crashMidStepDeliversEffectsExactlyOnce` crashes a real handler mid-message; both fail on any loss, duplication or misorder afterwards. |
| 4 | Same evidence as Fault model 1 plus `TargetedScenarioTest#causeOnPositionThatNeverYieldsResolvesFromReadPositionReport`: positions occupied by data the substrate never returns are the norm in the suite, not the exception. |
