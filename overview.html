Parsley is a Java library that provides causal delivery order for Kafka Streams processors. When the required conditions are met, every wrapped processor processes records in causal order, even when records originate from multiple topics and partitions. It does this by encoding each message's causal dependencies onto the message and buffering records until those dependencies have been observed.

The entire public surface lives in a single package, {@link io.github.tobyjamesclements.parsley}. The topology-level entry point is three roles mirroring Kafka Streams' own {@code StreamsBuilder} / {@code Topology} / {@code KafkaStreams}: {@link io.github.tobyjamesclements.parsley.CausalStreamsBuilder} declares one or more causal stages, {@code .build()} produces a {@link io.github.tobyjamesclements.parsley.CausalTopology}, and {@link io.github.tobyjamesclements.parsley.CausalStreams} is the runtime that wraps the underlying {@code KafkaStreams} instance. The low-level processor decorator that powers it, {@code ParsleyProcessorSupplier}, is package-private internal machinery, not constructed directly.

A running topology can also evolve — add a stage, replace a stage, recompile — across a leaderless epoch boundary: {@link io.github.tobyjamesclements.parsley.CausalStreams#requestEpochTransition()} evolves every participating member through it, so a new node adopts the current causal floor instead of replaying pre-epoch history into the shared frontier. This is optional and off by default; setting {@code parsley.coordination.epoch-events-topic} turns it on. Absent that key, a topology runs in epoch 0 indefinitely.

Core concepts

Causal dependencies
The positions a consumer must have observed before a record stamped with them may be delivered. They are a producer's snapshot of what it had seen when it sent the record. They are carried as {@link io.github.tobyjamesclements.parsley.CausalDependencies} in a {@code parsley-causal-dependencies} header. Build one from a consumed record by starting with {@link io.github.tobyjamesclements.parsley.CausalDependencies#using(java.util.Properties) using} to bind a topic resolver, then folding in each record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#observe observe}. Combine several for a fan-in with {@link io.github.tobyjamesclements.parsley.CausalDependencies#merge merge}, and attach the result to an outbound record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#stamp stamp}. When consuming a topic a Parsley topology produces, fold every record in with {@code observe} but skip those for which {@link io.github.tobyjamesclements.parsley.CausalDependencies#isWatermark isWatermark} returns true, which are protocol metadata rather than business records.
Completeness frontier
A node's own contiguous frontier max-merged with every input channel's advertised clock — the outbound stamp, carrying transitive ancestry downstream for each receiver's own gate to verify locally. The delivery gate itself checks the node's own contiguous frontier alone: a record is delivered once this node has itself delivered every coordinate the record depends on, and a peer's advertised claim never substitutes for local delivery. A dependency naming a coordinate this node has no input channel for is never treated as vacuously satisfied; it fails the task fast instead, so every input branch of a node must be able to observe every coordinate any branch's records depend on. The frontier is internal to Parsley's processor engine and is not a separate public type.
Protocol watermark
A record with a null value, keyed with the triggering record's key, marked with a {@code _parsley_watermark} header, that carries a node's completeness frontier downstream when a delivered input produced no business output. Reusing the key routes it to the same partition the record's output would. It keeps causal progress flowing through filters and not-yet-emitting aggregates, and relays further downstream only when the receiving channel's clock genuinely advanced — never unconditionally, which is what keeps a cyclic topology's marker traffic from ping-ponging forever. Parsley's processors handle watermarks internally; a plain Kafka client detects them with {@link io.github.tobyjamesclements.parsley.CausalDependencies#isWatermark isWatermark}.
Causal buffer
Records whose dependencies are not yet satisfied are held in an unbounded, changelog-backed buffer and released as soon as the frontier catches up. There is no configuration that trades causal order for liveness: a record whose dependencies are proven impossible — an undecodable payload or dependencies header, or a dependency naming a coordinate this node has no channel for — unconditionally fails the task rather than being dropped, evicted, or delivered out of order.

Entry points

TypePurpose
{@link io.github.tobyjamesclements.parsley.CausalStreamsBuilder}Declares one or more causal stages: {@code stream(...)} one or more source topics, {@code .process(supplier)} to bind them to a causal-decorated processor, {@code .to(...)} to declare its sink(s). {@code .build()} produces a {@link io.github.tobyjamesclements.parsley.CausalTopology}.
{@link io.github.tobyjamesclements.parsley.CausalTopology}The built causal topology — a specification, not yet a real Kafka Streams {@code Topology} — ready for {@code new CausalStreams(topology, props)}.
{@link io.github.tobyjamesclements.parsley.CausalStreams}The runtime: wraps the underlying {@code KafkaStreams} instance, and owns graceful causal drain on {@code close()} and, when {@code parsley.coordination.epoch-events-topic} is configured, topology-epoch coordination. Evolve a running topology through an epoch boundary with {@code requestEpochTransition()}.
{@link io.github.tobyjamesclements.parsley.CausalDependencies}Stamps and reads causal dependencies directly on plain {@code ProducerRecord} and {@code ConsumerRecord} objects, for talking to a Parsley topology from outside Kafka Streams.

Typical usage

{@code
CausalStreamsBuilder builder = new CausalStreamsBuilder();

builder.stream(List.of("prices", "orders"), Serdes.String(), orderSerde)
       .process(new EnrichOrderSupplier())
       .to("enriched-output", Serdes.String(), enrichedSerde);

CausalTopology topology = builder.build();

CausalStreams causalStreams = new CausalStreams(topology, props);
causalStreams.start();
Runtime.getRuntime().addShutdownHook(new Thread(causalStreams::close));

// At the edge, from a plain Kafka client
CausalDependencies deps = CausalDependencies.using(props).observe(consumedRecord);
producer.send(deps.stamp(new ProducerRecord<>("orders", key, value)));
}
