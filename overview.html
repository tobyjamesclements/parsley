Parsley is a Java library for causal consistency over Kafka. It ensures that every consumer processes messages in the correct causal order, even when records originate from multiple topics and partitions, by encoding each message's causal dependencies onto it and buffering records until those dependencies have been observed.

The entire public surface lives in a single package, {@link io.github.tobyjamesclements.parsley}, and consists of interfaces and value types; every implementation is package-private and obtained through a static factory ({@link io.github.tobyjamesclements.parsley.CausalProcessors}, {@link io.github.tobyjamesclements.parsley.CausalDependencies}, {@link io.github.tobyjamesclements.parsley.CausalTopics}).

Core concepts

Causal dependencies
The positions a consumer must have observed before a record stamped with them may be delivered — a producer's snapshot of what it had seen when it sent the record. Carried as {@link io.github.tobyjamesclements.parsley.CausalDependencies} in a {@code parsley-causal-dependencies} header. Build one from a consumed record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#from from}, combine several for a fan-in with {@link io.github.tobyjamesclements.parsley.CausalDependencies#merge merge}, and attach it to an outbound record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#stamp stamp}.
Causal frontier
The highest offset a causal processor has contiguously admitted on each topic-partition — never a coordinate it merely happens to have seen something later on, since a later-offset record may forward before an earlier one still held on the same partition. Keyed by topic UUID so that topic deletion and recreation produce a distinct identity even when the name is reused. A record is delivered once the frontier dominates its dependencies. The frontier is internal to {@link io.github.tobyjamesclements.parsley.CausalProcessors}; it is not a separate public type.
Causal buffer
Records whose dependencies are not yet satisfied are held in a changelog-backed buffer and released as soon as the frontier catches up. A {@link io.github.tobyjamesclements.parsley.CausalBufferLimit} bounds how long or how large the buffer may grow; Parsley never drops or diverts a record — when the limit fires, the held record is forwarded anyway, out of causal order, logged and counted as a violation.

Entry points

TypePurpose
{@link io.github.tobyjamesclements.parsley.CausalProcessorSupplier}Wraps a user Kafka Streams {@code Processor} so its state access and {@code forward}s run behind the causal guarantee; built via {@link io.github.tobyjamesclements.parsley.CausalProcessors}.
{@link io.github.tobyjamesclements.parsley.CausalDependencies}Stamps and reads causal dependencies directly on plain {@code ProducerRecord}/{@code ConsumerRecord} objects, for talking to a Parsley topology from outside Kafka Streams.

Typical usage

{@code
// Inside a Kafka Streams topology
builder.stream(List.of("prices", "orders"), Consumed.with(Serdes.String(), orderSerde))
       .process(CausalProcessors.builder(userSupplier)
               .addBufferStore("parsley", CausalBufferLimit.ofDuration(limit))
               .addBuffer(CausalBuffer.of("prices", Serdes.String(), priceSerde))
               .addBuffer(CausalBuffer.of("orders", Serdes.String(), orderSerde))
               .build())
       .to("output-topic");

// At the edge, from a plain Kafka client
CausalDependencies deps = CausalDependencies.from(topics, consumedRecord);
producer.send(deps.stamp(new ProducerRecord<>("orders", key, value)));
}
