Parsley is a Java library that provides causal delivery order for Kafka Streams processors. When the required conditions are met, every wrapped processor processes records in causal order, even when records originate from multiple topics and partitions. It does this by encoding each message's causal dependencies onto the message and buffering records until those dependencies have been observed.

The entire public surface lives in a single package, {@link io.github.tobyjamesclements.parsley}. It consists of interfaces and value types. Every implementation is package-private and obtained through a static factory: {@link io.github.tobyjamesclements.parsley.CausalProcessors}, {@link io.github.tobyjamesclements.parsley.CausalStreams}, and {@link io.github.tobyjamesclements.parsley.CausalDependencies}.

There are two entry points into the causal guarantee. {@link io.github.tobyjamesclements.parsley.CausalProcessors} is the low-level decorator: it wraps one user {@code Processor} and you wire it into a topology you build and own yourself. {@link io.github.tobyjamesclements.parsley.CausalStreams} is the high-level, topology-owning builder: it composes the same decorator internally, but owns the surrounding sources, processor, and sinks itself, which unlocks guarantees the decorator alone cannot provide — a sink partitioner applied uniformly across every sink, co-partitioning validation that covers sinks as well as inputs, and coordinated graceful shutdown via {@link io.github.tobyjamesclements.parsley.CausalQuiesce}.

A running topology can also evolve — add a stage, replace a stage, recompile — across a leaderless epoch boundary coordinated by {@link io.github.tobyjamesclements.parsley.CausalCoordination}, so a new node adopts the current causal floor instead of replaying pre-epoch history into the shared frontier. It is optional; without it a topology runs in epoch 0, unchanged.

Core concepts

Causal dependencies
The positions a consumer must have observed before a record stamped with them may be delivered. They are a producer's snapshot of what it had seen when it sent the record. They are carried as {@link io.github.tobyjamesclements.parsley.CausalDependencies} in a {@code parsley-causal-dependencies} header. Build one from a consumed record by starting with {@link io.github.tobyjamesclements.parsley.CausalDependencies#using using} to bind a topic resolver, then folding in each record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#observe observe}. Combine several for a fan-in with {@link io.github.tobyjamesclements.parsley.CausalDependencies#merge merge}, and attach the result to an outbound record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#stamp stamp}. When consuming a topic a Parsley topology produces, fold every record in with {@code observe} but skip those for which {@link io.github.tobyjamesclements.parsley.CausalDependencies#isWatermark isWatermark} returns true, which are protocol metadata rather than business records.
Causal frontier
The highest offset a causal processor has contiguously admitted on each topic-partition. It is never a coordinate the processor merely happens to have seen something later on, because a later-offset record may be forwarded before an earlier one that is still held on the same partition. The frontier is keyed by topic UUID, so topic deletion and recreation produce a distinct identity even when the name is reused. A record is delivered once every input channel has confirmed every coordinate the record depends on (the per-coordinate minimum across all input channels). The frontier is internal to {@link io.github.tobyjamesclements.parsley.CausalProcessors} and is not a separate public type.
Protocol watermark
A record with a null value, keyed with the triggering record's key, marked with a {@code _parsley_watermark} header, that carries a node's completeness frontier downstream when a delivered input produced no business output. Reusing the key routes it to the same partition the record's output would. It keeps causal progress flowing through filters and not-yet-emitting aggregates. Parsley's processors handle watermarks internally; a plain Kafka client detects them with {@link io.github.tobyjamesclements.parsley.CausalDependencies#isWatermark isWatermark}.
Causal buffer
Records whose dependencies are not yet satisfied are held in a changelog-backed buffer and released as soon as the frontier catches up. A {@link io.github.tobyjamesclements.parsley.CausalBufferLimit} bounds how long or how large the buffer may grow. When the limit fires before a held record's dependencies are satisfied, the outcome is governed by the {@code parsley.buffer.eviction.failure.policy} configuration. By default Parsley fails the task and leaves the record buffered for retry, which keeps delivery in causal order. Setting the policy to {@code continue} forwards the held record out of causal order instead. Parsley never drops or diverts a record under either policy, and every firing is logged and counted.

Entry points

TypePurpose
{@link io.github.tobyjamesclements.parsley.CausalProcessorSupplier}Wraps a user Kafka Streams {@code Processor} so that its state access and its {@code forward} calls run behind the causal guarantee. It is built through {@link io.github.tobyjamesclements.parsley.CausalProcessors}.
{@link io.github.tobyjamesclements.parsley.CausalStreams}The topology-owning builder: composes {@link io.github.tobyjamesclements.parsley.CausalProcessors} internally and owns the sources, processor, and sinks around it, so it can apply a uniform sink partitioner and validate co-partitioning across sinks as well as inputs.
{@link io.github.tobyjamesclements.parsley.CausalQuiesce}A shared handle for coordinating graceful shutdown across every causal task in one application instance. Register it via {@code withQuiesce} on either builder; call {@code requestQuiesce()} and poll {@code isSafeToClose()} before closing {@code KafkaStreams}.
{@link io.github.tobyjamesclements.parsley.CausalCoordination}A shared, leaderless handle for evolving a running topology across an epoch boundary, so a new or replaced stage adopts the current causal floor rather than replaying pre-epoch history into the shared frontier. Register it via {@code withCoordination} on either builder; call {@code requestEpochTransition()} to evolve, and {@code close()} in shutdown. Optional — without it a topology runs in epoch 0.
{@link io.github.tobyjamesclements.parsley.CausalDependencies}Stamps and reads causal dependencies directly on plain {@code ProducerRecord} and {@code ConsumerRecord} objects, for talking to a Parsley topology from outside Kafka Streams.
{@link io.github.tobyjamesclements.parsley.CausalAudit}Optional callback interface supplied to the builder via {@link io.github.tobyjamesclements.parsley.CausalProcessors.Builder#withAudit withAudit}. Receives per-record buffering events — forwarded, held, released, evicted, and deserialization failures — carrying record identity and causal metadata only, never the record payload.

Typical usage

{@code
// Low-level: inside a Kafka Streams topology you build and own
builder.stream(List.of("prices", "orders"), Consumed.with(Serdes.String(), orderSerde))
       .process(CausalProcessors.builder(userSupplier)
               .addBufferStore("parsley", CausalBufferLimit.ofDuration(limit))
               .addBuffer(CausalBuffer.of("prices", Serdes.String(), priceSerde))
               .addBuffer(CausalBuffer.of("orders", Serdes.String(), orderSerde))
               .build())
       .to("output-topic");

// High-level: CausalStreams owns the topology itself
Topology topology = CausalStreams.builder(userSupplier)
        .addBufferStore("parsley", CausalBufferLimit.ofDuration(limit))
        .addSource(CausalBuffer.of("prices", Serdes.String(), priceSerde))
        .addSource(CausalBuffer.of("orders", Serdes.String(), orderSerde))
        .addSink("enriched-sink", "enriched-output", Serdes.String(), enrichedSerde)
        .build();
new KafkaStreams(topology, props).start();

// At the edge, from a plain Kafka client
CausalDependencies deps = CausalDependencies.using(topics).observe(consumedRecord);
producer.send(deps.stamp(new ProducerRecord<>("orders", key, value)));
}
