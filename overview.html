Parsley is a Java library that provides causal consistency over Kafka. It ensures that every consumer processes messages in the correct causal order, even when records originate from multiple topics and partitions. It does this by encoding each message's causal dependencies onto the message and buffering records until those dependencies have been observed.

The entire public surface lives in a single package, {@link io.github.tobyjamesclements.parsley}. It consists of interfaces and value types. Every implementation is package-private and obtained through a static factory: {@link io.github.tobyjamesclements.parsley.CausalProcessors}, {@link io.github.tobyjamesclements.parsley.CausalDependencies}, and {@link io.github.tobyjamesclements.parsley.CausalTopics}.

Core concepts

Causal dependencies
The positions a consumer must have observed before a record stamped with them may be delivered. They are a producer's snapshot of what it had seen when it sent the record. They are carried as {@link io.github.tobyjamesclements.parsley.CausalDependencies} in a {@code parsley-causal-dependencies} header. Build one from a consumed record by starting with {@link io.github.tobyjamesclements.parsley.CausalDependencies#using using} to bind a topic resolver, then folding in each record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#observe observe}. Combine several for a fan-in with {@link io.github.tobyjamesclements.parsley.CausalDependencies#merge merge}, and attach the result to an outbound record with {@link io.github.tobyjamesclements.parsley.CausalDependencies#stamp stamp}.
Causal frontier
The highest offset a causal processor has contiguously admitted on each topic-partition. It is never a coordinate the processor merely happens to have seen something later on, because a later-offset record may be forwarded before an earlier one that is still held on the same partition. The frontier is keyed by topic UUID, so topic deletion and recreation produce a distinct identity even when the name is reused. A record is delivered once the frontier dominates its dependencies. The frontier is internal to {@link io.github.tobyjamesclements.parsley.CausalProcessors} and is not a separate public type.
Causal buffer
Records whose dependencies are not yet satisfied are held in a changelog-backed buffer and released as soon as the frontier catches up. A {@link io.github.tobyjamesclements.parsley.CausalBufferLimit} bounds how long or how large the buffer may grow. When the limit fires before a held record's dependencies are satisfied, the outcome is governed by the {@code parsley.buffer.eviction.failure.policy} configuration. By default Parsley fails the task and leaves the record buffered for retry, which keeps delivery in causal order. Setting the policy to {@code continue} forwards the held record out of causal order instead. Parsley never drops or diverts a record under either policy, and every firing is logged and counted.

Entry points

TypePurpose
{@link io.github.tobyjamesclements.parsley.CausalProcessorSupplier}Wraps a user Kafka Streams {@code Processor} so that its state access and its {@code forward} calls run behind the causal guarantee. It is built through {@link io.github.tobyjamesclements.parsley.CausalProcessors}.
{@link io.github.tobyjamesclements.parsley.CausalDependencies}Stamps and reads causal dependencies directly on plain {@code ProducerRecord} and {@code ConsumerRecord} objects, for talking to a Parsley topology from outside Kafka Streams.
{@link io.github.tobyjamesclements.parsley.CausalAudit}Optional callback interface supplied to the builder via {@link io.github.tobyjamesclements.parsley.CausalProcessors.Builder#withAudit withAudit}. Receives per-record buffering events — forwarded, held, released, evicted, and deserialization failures — carrying record identity and causal metadata only, never the record payload.

Typical usage

{@code
// Inside a Kafka Streams topology
builder.stream(List.of("prices", "orders"), Consumed.with(Serdes.String(), orderSerde))
       .process(CausalProcessors.builder(userSupplier)
               .addBufferStore("parsley", CausalBufferLimit.ofDuration(limit))
               .addBuffer(CausalBuffer.of("prices", Serdes.String(), priceSerde))
               .addBuffer(CausalBuffer.of("orders", Serdes.String(), orderSerde))
               .build())
       .to("output-topic");

// At the edge, from a plain Kafka client
CausalDependencies deps = CausalDependencies.using(topics).observe(consumedRecord);
producer.send(deps.stamp(new ProducerRecord<>("orders", key, value)));
}
